Infera API

An OpenAI-compatible API served by idle phones, laptops and desktops. If your code works with OpenAI, change the base URL and key and it works with Infera.

Base URL:  https://infera.valanor.network/v1

Quickstart

  1. Create a developer account and copy your API key (ik_cust_…). New accounts get starter credits.
  2. Send a request:
curl https://infera.valanor.network/v1/chat/completions \
  -H "Authorization: Bearer $INFERA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "qwen3-4b", "messages": [{"role": "user", "content": "Hello!"}]}'
from openai import OpenAI

client = OpenAI(base_url="https://infera.valanor.network/v1", api_key="ik_cust_…")
r = client.chat.completions.create(
    model="qwen3-4b",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(r.choices[0].message.content)
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "https://infera.valanor.network/v1", apiKey: "ik_cust_…" });
const r = await client.chat.completions.create({
  model: "qwen3-4b",
  messages: [{ role: "user", content: "Hello!" }],
});
console.log(r.choices[0].message.content);

Authentication

Send your key as a bearer token on every request: Authorization: Bearer ik_cust_…. Keys are shown once when created; we store only a hash. Keep keys server-side.

Chat completions

POST/v1/chat/completions, the same request and response as OpenAI's Chat Completions.

FieldTypeNotes
modelstringRequired. A chat model from /v1/models.
messagesarrayRequired. {"role": "system"|"user"|"assistant", "content": "…"}
max_tokensintegerAnswer length limit. Default 512.
temperaturenumber0 for repeatable answers. Default 0.7.
streambooleanServer-sent events, like OpenAI. Reasoning models stream thinking as reasoning_content.
infera_batchbooleanOptional: marks a request that can tolerate slower devices.
curl https://infera.valanor.network/v1/chat/completions \
  -H "Authorization: Bearer $INFERA_API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"qwen3-4b","stream":true,"max_tokens":200,
       "messages":[{"role":"user","content":"Explain DePIN in one paragraph."}]}'

Responses carry X-Infera-Job (the job id) and X-Infera-Route (device or fallback).

Completions (code autocomplete)

POST/v1/completions, OpenAI's text-completion format. For code, send the text before the cursor as prompt and the text after it as suffix ("fill in the middle"). Best with the coder models: qwen2.5-coder-1.5b, qwen2.5-coder-3b, qwen2.5-coder-7b, qwen2.5-coder-14b, qwen3-coder-30b-a3b.

curl https://infera.valanor.network/v1/completions \
  -H "Authorization: Bearer $INFERA_API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"qwen2.5-coder-1.5b","prompt":"def add(a, b):\n    ","suffix":"\n\nprint(add(1, 2))","max_tokens":32,"temperature":0}'
# → {"object":"text_completion","choices":[{"text":"return a + b", ...}], "usage": {...}}

Fields: model, prompt (string), suffix, max_tokens (default 128), temperature, stop, stream.

Tool calling (coding agents)

Chat completions accept OpenAI tools. When the model calls a tool, the response has message.tool_calls and finish_reason: "tool_calls" (streamed as delta.tool_calls). Send the result back as a role: "tool" message with the matching tool_call_id. Requests with tools go to computers (not phones); coder models on large machines serve a 32K-token context.

curl https://infera.valanor.network/v1/chat/completions \
  -H "Authorization: Bearer ik_cust_…" -H "Content-Type: application/json" \
  -d '{"model": "qwen2.5-coder-7b",
       "messages": [{"role": "user", "content": "Open main.py"}],
       "tools": [{"type": "function", "function": {"name": "read_file",
         "parameters": {"type": "object", "properties": {"path": {"type": "string"}}}}}]}'

Cline / Roo Code: provider OpenAI Compatible, base URL https://infera.valanor.network/v1, your API key, model qwen2.5-coder-14b. Aider: aider --openai-api-base https://infera.valanor.network/v1 --openai-api-key ik_cust_… --model openai/qwen2.5-coder-14b.

Embeddings

POST/v1/embeddings, same as OpenAI. input is a string or an array of strings.

curl https://infera.valanor.network/v1/embeddings \
  -H "Authorization: Bearer $INFERA_API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"nomic-embed-text","input":["idle phones","serve AI"]}'

Transcriptions (speech to text)

POST/v1/audio/transcriptions, multipart form, same as OpenAI's Whisper API. Billed per audio minute.

FieldNotes
fileRequired. Audio up to 25 MB: mp3, m4a, wav, ogg, flac, webm…
modelRequired. whisper-base
languageOptional ISO code, e.g. en. Default: detect.
promptOptional context to guide spelling.
response_formatjson (default), text or verbose_json (adds language, duration and timed segments).
curl https://infera.valanor.network/v1/audio/transcriptions \
  -H "Authorization: Bearer $INFERA_API_KEY" \
  -F model=whisper-base -F file=@meeting.mp3 -F response_format=verbose_json
# Python
with open("meeting.mp3", "rb") as f:
    t = client.audio.transcriptions.create(model="whisper-base", file=f)
print(t.text)

Batch API

For work that can wait up to 24 hours, at a discount (50% off). Jobs run whenever a suitable device is free, phones included.

POST/v1/batch: up to 1,000 requests per call (chat or embeddings). Returns job ids.

curl https://infera.valanor.network/v1/batch \
  -H "Authorization: Bearer $INFERA_API_KEY" -H "Content-Type: application/json" \
  -d '{"requests":[
        {"model":"qwen3-4b","max_tokens":100,"messages":[{"role":"user","content":"Summarise: …"}]},
        {"model":"nomic-embed-text","input":"text to embed"}
      ]}'
# → {"ids":["bj_…","bj_…"]}

GET/v1/batch/{id}: status (queued, running, done, failed) and the result. GET/v1/batch?status=done lists your recent jobs. Results are kept for 7 days after a job finishes.

List models

GET/v1/models is public. Each model has pricing (USD per token as strings, or per audio minute), context_length, quantization, endpoint and devices_online.

SDKs & tools

Anything that accepts an OpenAI base URL works. Set the base URL to https://infera.valanor.network/v1 and use your Infera key:

  • OpenAI SDKs (Python, JavaScript, Go, …): base_url / baseURL.
  • LangChain: ChatOpenAI(base_url=…, api_key=…, model="qwen3-4b").
  • LlamaIndex: OpenAILike(api_base=…, api_key=…, model="qwen3-4b", is_chat_model=True).
  • LiteLLM: model="openai/qwen3-4b", api_base=…, api_key=….
  • n8n, Zapier, Make: use the OpenAI node/action with a custom base URL.

How requests are served

  • Each request is encrypted to one device (a fresh key per job) and streamed back as it's generated.
  • If the first device hasn't started answering in about 2.5 s, a second device gets the request too; the first to answer wins and you're billed once.
  • Devices sign a receipt for every answer; test prompts and re-runs on a second device catch wrong results.
  • When no device is free, a request may go to rented cloud capacity (X-Infera-Route: fallback) or return 503.
  • Live speed and uptime per model: /performance.

Errors

Errors use OpenAI's shape: {"error": {"message": "…", "code": 400}}.

CodeMeaningWhat to do
400Bad request (missing model/messages, file too big…)Fix the request.
401Missing or invalid API keyCheck the Authorization header.
402Not enough creditsTop up on the dashboard.
404Batch job not foundCheck the id.
429Rate limit or too many requests at onceRetry after the time in the message.
503No device is serving that model right nowRetry shortly, try another model, or use the batch API.

Rate limits

By default each key can send 120 requests a minute with up to 8 in progress at once. Need more? Email hello@valanor.network.

Privacy

Our servers never store the content of live requests; batch content is deleted 7 days after completion. Requests run on independent contributors' devices, so don't send secrets or personal data yet. Details: Data and privacy · Privacy policy · Terms.
